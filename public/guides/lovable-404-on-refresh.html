Why does my Lovable app show 404 when I refresh the page?

Written 18 November 2026. Every source below was opened and checked on the date given.

Short answer: your app has only one real page file. React builds the other addresses in the browser, so when you refresh /dashboard the host looks for a file called dashboard, cannot find one, and answers 404. The fix is one rule telling the host to serve index.html for every address.

Nothing is wrong with your code, your database or your build. This is a host setting, and it is two lines in one file.

How to tell this is your problem

  • The home page works. The app only breaks when you refresh a page inside it, or when someone opens a link you shared.
  • Clicking through the app from the home page works fine.
  • You see your host’s 404 page, not your own, and not a blank screen. A blank screen with no error is a different problem: run a free check and it will tell you which one you have.

When it happens, and when it does not

You usually will not see this on a lovable.app address. On 18 November 2026 we checked 35 live Lovable apps from outside and not one of them 404ed on a deep link, because Lovable’s own hosting already applies the rule. That is our own measurement, not a claim from Lovable.

It appears once the app is served by something you set up yourself: you exported the code to GitHub and deployed it to Netlify, Vercel or your own server, or you are hosting the built files on ordinary web hosting. Each of those needs telling.

Netlify

Add a file called _redirects in your published folder containing one line:

/*  /index.html  200

Or put the same rule in netlify.toml at the top of your project:

[[redirects]]
from = "/*"
to = "/index.html"
status = 200

Netlify’s own documentation gives exactly these two forms and says the rule “will effectively serve the index.html instead of giving a 404 no matter what URL the browser requests” (Netlify docs: Rewrites and proxies, read 18 November 2026). Status 200 matters: it serves your app at the address the visitor typed instead of sending them somewhere else.

Vercel

Add vercel.json at the top of your project:

{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}

Rewrites in Vercel are defined in vercel.json with a source and a destination, and regular expressions are allowed in source (Vercel docs: Rewrites, read 18 November 2026). One caveat from that same page: if your project is Next.js, Astro or SvelteKit, use the framework’s own routing rather than this rule. A plain Vite and React app, which is what Lovable produces, has no framework routing of its own, so the rule above is the right place.

Any other host

The rule is always the same sentence in a different accent: for any address that is not a real file, serve index.html with a 200. If you are on shared hosting or your own server, that is what to ask your host’s support for. Do not let anyone talk you into a 301 or 302 redirect to the home page: that loses the address the visitor asked for, so shared links stop working even though the 404 goes away.

If you would rather your builder did it

Paste this into Lovable, Bolt or Cursor:

My deployed app returns 404 when I refresh any page other than the home page,
because the host does not know this is a single-page app. Add the correct
single-page-app rewrite for the host I am deploying to, serving index.html with
status 200 for any path that is not a real file. Tell me which file you created
or changed and what I need to do on the host. Change nothing about my routes or
components.

How to check it worked

Open a page inside your app, copy the address from the bar, paste it into a private window and press enter. If the app loads, it is fixed. Unbork checks the same thing from outside, free, with no sign-up.
